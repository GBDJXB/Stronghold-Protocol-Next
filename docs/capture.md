# 单次截图设计与存档

## 状态与范围

本文保留“已确认的后续需求基线”作为完整目标记录，并在其后更新当前实现状态。当前使用项目内原生 WGC 后端。它仍是初步实现，离线验证不代表实机截图、遮挡检测完整性或性能目标已经验收。真实游戏截图需另行决定并在独立测试对话进行。

## 已确认的后续需求基线

### 采集与调度

- 以按需采集为主；休整回合后的对局期间目标每秒一张，用于发现干员倒地等持续状态。允许漏掉两次采样之间未留下持续可见结果的短暂事件，不要求精确还原全部事件时刻。
- 所有来源共用至少 500 ms 的采集启动间隔，同一时间最多一次采集。忙碌或间隔未到时立即返回“暂不可发起”和建议重试时间，不排队，也不计入连续采集失败。通过限流和采集优化尽量避免请求排队。
- 每张成功截图，包括周期截图，均保存 PNG 和 `metadata.json`。现阶段不要求滚动删除或容量上限；后续可再决定精简存档。不重新引入截图 SHA-256 或额外完整性校验，SDK 下载校验仍独立保留。
- 截图组件负责图像数据、来源、新鲜度信息及存档，报告可检测异常；不保证游戏内容正确或适合分析。加载动画和游戏状态由下游视觉组件判断。截图成功不等于内容适合决策。

### 可见性与新鲜度

- 窗口未聚焦但客户区完整可见时，允许按需采集。不得抢焦点、移动或缩放游戏窗口、修改其透明度或妨碍用户操作；不得通过恢复窗口、伪最小化或其他窗口状态变更强行采集。
- 最小化、隐藏、完全移出屏幕、客户区被任何其他可见窗口覆盖任意部分，或游戏窗口自身非完全不透明，均视为不可见。任务栏、通知和小浮窗覆盖客户区也算；只覆盖标题栏或边框、鼠标指针及窗口阴影不算。窗口自身透明不包括游戏内半透明菜单、淡入淡出、黑屏或亮度变化。部分离屏允许该请求失败。
- 采集前后检查可见性，采集中接受每秒检查一次；允许遗漏两次检查之间出现又消失的短暂异常。发现异常后停止实际采集，丢弃尚未发布的结果；不可见期间只复查条件。未检测到异常不等于已证明完全可见。
- 目标是交付时画面年龄不超过 1 秒。过期或无法确认新鲜度的画面不能直接作为已确认的当前状态驱动操作。画面相同不能直接判为过期，请求完成时间不能充当源帧时间；允许请求偶尔较慢不改变新鲜度要求。

### 下游队列、失败和恢复

以下是完整 pipeline 的需求，组件划分和具体接口待设计，不要求全部由基础截图组件承担。

- 待识别队列仅指已采集、等待识别的截图，默认容量 3 且可配置。队列已有 3 张时收到新图，清空旧队列并记录丢弃数，再接受新图；不强行中断正在识别的任务，也不删除已存 PNG 或元数据。过期识别结果可用于历史记录，不能直接驱动当前操作。
- 正常显示、无遮挡且未调整尺寸时，采集失败或超时率目标不超过 1%（每 1000 次最多 10 次）；用户引发的遮挡、最小化等单独统计。将错误画面报告为正常可用是缺陷，不计入该容忍预算。
- 连续 3 次采集失败或前置条件不满足时暂停代打；成功一次清零，失败后约 1 秒重试。暂停时间包含请求耗时，不保证恰好 3 秒；不另设此前讨论过的 3 秒或 10 秒门槛。
- 暂停当前代打、记录断点，保留进程等待恢复。用户或外部模型均可通过 PowerShell 命令请求恢复；条件自行恢复时程序不能自动继续代打。命令名尚未确定。恢复时先检查窗口条件、取得可靠新截图，再由下游重新确认当前游戏状态；成功才恢复，失败保持暂停并返回原因，不假定等待期间游戏状态不变。

### 兼容性与观测目标

- 首版以本机现有显示配置验收，窗口模式和无边框模式必须可用，覆盖实际 DPI、多显示器和分辨率。独占全屏、HDR、远程桌面及其他电脑暂非硬要求。
- 初期以能运行为优先。正常采集目标为每秒 1 张，绝大多数正常请求在 1 秒内交付图像和元数据，偶发可到 2 秒；启动或恢复的初始化及首张截图目标为 5 秒。这些是观测和优化目标，不是初期功能验收硬门槛；记录实际耗时，不能宣称未经测量的性能。
- 所有截图相关进程合计峰值内存目标不超过 512 MiB，不含后续识别模型。正常每秒采集并落盘时，与同场景未启用截图相比，游戏平均帧率下降目标不超过 5%，同时检查明显卡顿。不另设 CPU/GPU 占用率上限，但记录实际开销；PNG 磁盘占用实测。上述资源目标均待实测。

## 当前实现

### 接口与采集流程

生产入口为 `capture_and_save`，统一执行进程内限流、捕获、校验与归档；`capture_window` 是底层接入入口，不单独做准入控制。流程为：窗口选择 → 可见性/来源检查 → 隔离工作进程采集 → 父进程周期复核 → 图像校验 → 临时目录写入 PNG/metadata → 发布前复核 → 同卷重命名 → 交付年龄复查。当前 CLI 不实现周期触发、识别队列、暂停/恢复或代打。

CLI 查找唯一可选游戏窗口，或通过 `--hwnd` 指定。`--method auto` 与 `--method wgc` 都只走原生 Windows Graphics Capture。`--check-backend` 仅检查 `GraphicsCaptureSession::IsSupported`，不获取窗口或帧。

进程启用 per-monitor-v2 DPI。窗口身份首选 HWND、PID、进程创建 FILETIME、可执行路径及窗口类，并比较物理客户区位置/尺寸。若进程查询因 `ERROR_ACCESS_DENIED` 受限，且窗口类/标题足以进行启发式游戏筛选，则身份标记为 limited，未知的路径和创建时间按 `null` 存档；如果复核时身份从 verified 降为 limited 或来源/几何发生变化，则拒绝采集。程序不自动提权。此识别不是对游戏二进制签名或真实性的证明。

`wait_foreground` 是遗留辅助函数，内部以 1 Hz 检查并等待前台；生产调用链不使用它，也不要求窗口获得焦点。

### 被动性与可见性边界

WGC 路径不调用置前、移动/缩放、恢复窗口、伪最小化或透明度修改接口，也不发送鼠标/键盘输入。捕获会话显式禁用鼠标指针图像。Windows 系统默认捕获边框策略保持原样，系统可能显示捕获边框/指示。

采集前后及发布前由父进程复核窗口条件；工作进程采集中由父进程约每秒复核，另有采集开始/结束检查。若身份、可见性或几何检查失败，结束工作进程并清理尚未发布的结果。轮询是离散采样，不能发现采样之间发生并恢复的短暂变化。

可见性采用 Win32 窗口状态、DWM cloaking、DWM 扩展帧边界、显示器矩形、窗口 z-order 与可取得的窗口 region 做保守判定。隐藏、最小化、DWM cloaked、部分离屏、属性可知的非不透明窗口、已知客户区遮挡和检测不确定均拒绝。遮挡窗口的 region 不可取得时使用其可见框矩形保守判断；遇到查询失败或状态未知则拒绝。对非 layered 目标窗口只能由普通窗口属性判为 opaque，不能保证捕获所有 DirectComposition/自定义合成透明效果；因此“clear/opaque”是属性检查结果，不是对最终屏幕像素完全可见的证明。WGC 输出本身也不进行像素级遮挡清除。游戏内半透明菜单、黑屏或内容质量不在此判定范围。

### 源帧新鲜度与归档

WGC 帧的 `SystemRelativeTime` 被保存为 QPC 时钟域的 100 ns 计数，只能在同一系统启动周期比较，不可跨重启用历史 QPC 计算当前年龄。工作进程只接受年龄不超过 1000 ms 的帧，并在像素拷贝后复核一次；无时间戳、未来时间或截止前无新鲜帧会失败。工作进程最多等待 8 秒，但等待时长与帧年龄是不同量；长等待可能拉长请求，成功仍以源帧年龄判定。

成功采集的画面总会尝试归档，不因 PNG 编码耗时越过 1 秒而删除。metadata 在 PNG 编码完成后、写入 metadata 前测量 `frame_age_ms_at_archive_check` 与 `frame_freshness`；CLI 在目录发布后重新检查，并返回 `frame_age_ms_at_delivery_check` 与 `frame_freshness_at_delivery_check`。若元数据写入、复核或发布耗时使年龄跨过阈值，metadata 可能仍为 fresh，而 CLI 返回 stale。`fresh` 为年龄 ≤1000 ms，`stale` 为超过 1000 ms，`unknown` 为无可用年龄。stale/unknown 结果只能用于历史留档，不可直接作为已确认的当前状态驱动操作。

图像为 packed RGB8，按 WGC 客户区几何裁出原始像素，不缩放、不移除黑边；源 Capture 在归档时只读借用，PNG 编码使用临时颜色转换缓冲。拒绝非法尺寸/长度、客户区尺寸不匹配和全黑图像；至少 99% 通道值不超过 8 时添加 `near_black_image` 警告但仍保存。此规则不判断游戏状态或加载动画。

归档目录先写 `.tmp-<GUID>`，包含 `raw.png` 与 UTF-8 `metadata.json`，在发布前复核窗口后原子重命名为 GUID 目录。复核/写入失败时清理临时目录；不承诺断电耐久性。无哈希/CRC；后续分析应另存并引用 `frame_id`，不覆盖原始图像。

### metadata schema 2

| 字段 | 含义 |
| --- | --- |
| `schema_version`, `frame_id` | 版本 2；GUID 与目录名一致 |
| `request_start`, `request_end`, `duration_ms` | UTC 请求时间及采集时长，不代表源帧时间 |
| `method`, `backend` | 方法名；固定 `{name: windows-graphics-capture, implementation: stronghold-wgc-v1}` |
| `source_frame` | `{clock: qpc, unit: 100ns, time: string|null}`；大整数使用十进制字符串 |
| `frame_freshness`, `frame_age_ms_at_archive_check` | PNG 编码后、metadata 写入前的检查结果和年龄 |
| `window` | HWND/PID、身份是否 verified、未知来源字段为 null、窗口类/标题/客户区、可见/最小化/前台/离屏、opacity、visibility、cloaked、occluding HWND 和身份警告 |
| `raw` | 相对路径、尺寸及 RGB8 格式 |
| `attempts`, `warnings` | 后端结果及采集/图像质量警告 |
| `performance` | `encoding_ms`、`archive_elapsed_ms`、`png_bytes`，以及父进程和工作进程分别记录的 working-set 峰值字节 |

`archive_elapsed_ms` 是归档检查点耗时，不是发布后 CLI 交付耗时。两个进程的 working-set 峰值分别记录，不能当作进程合计峰值；GPU 内存也不包含在内。实际磁盘、延迟、内存、GPU 和游戏帧率影响均待测。

`window.process_created` 与源帧时标均使用十进制字符串或 null，避免双精度 JSON 消费者损失 64 位精度。`capture_json` 仅生成稳定预览，没有执行归档检查，因此其年龄为 unknown、归档性能为零；真实存档字段由 `save_capture` 测量。发布后的帧龄回查若因时钟错误失败，仍返回已发布路径并标 unknown，不把已发布记录反报为保存失败。

WGC 客户区裁切参考 DWM 扩展帧边界映射纹理原点，并严格校验目标/纹理尺寸。尺寸一致不能单独证明坐标原点完全一致；窗口边界四侧像素必须纳入实机验收。

### 准入与错误处理

生产 `capture_and_save` 用进程内共享 gate：同时最多一个请求，成功进入后 500 ms 内不接受下一次开始。busy/throttle 请求立即抛出 `AdmissionError`，给出建议等待时间，不排队。该 gate 不跨独立 CLI 进程共享，也不是单实例锁；未来主应用需实现应用级单实例与统一调用。

父进程通过 Windows Job 管理隔离工作进程；worker 异常、超时、IPC 不完整、窗口状态变化或存档错误均返回分类错误，不使用备用截图后端绕过失败。错误 JSON 不承诺覆盖所有 Windows 系统错误细节。

## 当前检查与实机边界

离线检查使用合成图、模拟状态及隔离子进程，不读取桌面或启动游戏。执行情况和实际结果以对应构建/检查输出为准；本设计文档不预先宣称某次检查已通过。实机尚需验证窗口模式/无边框模式、DPI、多显示器、分辨率、前后台、遮挡、离屏、透明度、系统捕获边框、保存时延与资源开销。遮挡检测的属性局限以及非 layered 合成透明状态尤其需要实机检查。

每秒一张、通常 1 秒交付、首帧 5 秒、512 MiB 进程总内存和平均帧率下降不超过 5% 等均是待观测目标，不是已测性能或当前硬保证。进程级 working set 不等于总内存，也不含 GPU 内存。独占全屏、HDR、远程桌面及其他电脑仍不在首版硬要求内。
