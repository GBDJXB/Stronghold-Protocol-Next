# 03: 全量重建与历史快照隔离

**What to build:** 用户在赛季或资料发生变化时，能从新的本地来源材料重建整个声明覆盖范围，校验后形成独立新快照；新旧快照均可显式查询，更新失败不破坏旧数据。

**Blocked by:** 02: 三盟约三干员的关系、特质及候选查询。

**Status:** resolved

父规格：[卫戍协议静态知识库](../spec.md)。全量指快照声明的覆盖范围，不要求完整赛季数据库。

- [x] 从新来源材料完整重建所声明覆盖范围，不逐条混入旧快照记录；赛季／序列语境与来源修订分别保留，客户端构建未知时仍为未知。
- [x] 新快照具备独立 snapshot_id 和来源指纹，既有标识不被覆盖；明确处理重复导入，不静默替换已有内容。
- [x] 提取和校验全部成功后才发布完整快照；失败或中断不会产生可查询半成品，也不破坏此前可用快照。
- [x] 查询始终显式选择快照；新快照发布后，相同旧标识的查询结果及来源不变，不通过隐式“最新”改变历史查询。
- [x] 通过两套可区分的离线来源材料，从公共入口验证新增、修改及移除，证明重建不会残留已移除条目或污染旧快照；合成变更只作为软件行为验证，不声称真实新赛季兼容。
- [x] 验证损坏或矛盾输入导致重建失败后，旧快照仍可查询；知识快照损坏、不支持版本和不存在标识分别有明确错误。
- [x] 使用说明明确手动获取与导入、赛季全量更新、来源核对和历史查询步骤，说明覆盖及适用版本限制。无定时联网、自动客户端版本探测或自动对外分发。

## Comments

- 首版不要求恢复全部历史模板依赖；固定来源材料的可重跑、历史依赖追溯和游戏适用性三个层级继续分别报告。
- 不修改原 OCR 承包范围、state-recognition spec 或 ticket 02 验收，不自动提交或推送。
